# amagadon

아마게돈 Windows 런처. 게임 데이터는 포함하지 않습니다.

## 실행

`dist/0.3.13-release/AmagadonLauncher-0.3.13.exe`를 실행하고 게임 설치 폴더를 지정합니다.
기본 경로: `C:\Users\seo\Downloads\armaggeddon\armaggeddon`.
배포 ZIP은 전체를 풀어 사용합니다. `compat`, `apply-update.ps1` 파일도 필요합니다.

- **게임 실행**: 게임 폴더를 작업 디렉터리로 지정해 실행합니다.
- **맵 에디터 실행**: 원본 ACE.exe를 보존한 별도 ACE.Compat.exe에 영역별 GDI 출력 패치를 적용해 실행합니다. 게임의 그래픽 프로필을 잠시 분리하고 종료 후 복원합니다.
- **내부 해상도**: 원본 800×600 또는 실제 1024×768(4:3) 시야 확장 모드. 별도 Armageddon.HD-preview.exe를 생성하며 원본은 보존합니다. 기본 출력은 모니터 해상도를 유지하는 테두리 없는 전체 화면 늘리기(레터박스 없음)입니다. 와이드 모니터에서는 가로로 늘어납니다. 출력 확대·종횡비·창/전체 화면·렌더러·커서 제한도 선택할 수 있습니다.
- **그래픽 호환성**: cnc-ddraw 7.1.0, 단일 CPU, 프레임 제한, 비독점 창 모드. 모든 크래시 해결을 보장하지 않습니다.
- **호환성 복원**: 원래 DLL/설정을 복원합니다. 백업은 게임 폴더 `LauncherBackups`에 유지됩니다.
- **업데이트**: 이 저장소의 최신 GitHub Release를 확인합니다. ZIP과 SHA-256 검증 파일이 있어야 설치됩니다. 기존 파일을 백업한 뒤 런처를 교체합니다.
- **생산 랠리**: 랠리포인트 방향의 건물 측면에서 출구를 먼저 탐색하고, 막히면 원본 충돌 검사로 다른 출구를 찾습니다.
- **진단/리포트**: 진단 기록이 기본 활성화됩니다. 마우스·프로세스 상태와 충돌 덤프를 로컬에 수집하고 **로깅 리포트 ZIP** 버튼으로 저장합니다. 마우스 입력 호환 모드는 기본 활성화되며 이전 설정도 한 번 갱신합니다. 입력 정지 의심 시 실행당 한 번 진단 덤프를 추가 수집합니다. Ctrl+Tab으로 커서 제한을 해제할 수도 있습니다.
- **패치노트**: 동봉한 PATCHNOTES.md를 표시합니다.

설정/로그: `%LOCALAPPDATA%\AmagadonLauncher`. 게임과 에디터는 동시에 실행하지 않습니다.

## 게임 리플레이 (0.3.3-preview · 실험)

1. 내부 해상도 **1024×768**을 선택하고 **싱글플레이 리플레이 자동 기록**을 켭니다.
2. 게임을 실행해 싱글플레이를 진행합니다. 대전 종료 또는 정상 게임 종료 후 `.agr` 파일을 자동 저장합니다.
3. **리플레이 저장 폴더**에서 파일을 확인하고 **리플레이 재생**의 최신순 목록에서 더블클릭 또는 Enter로 즉시 재생합니다. 재생은 시작 상태를 자동으로 불러옵니다. 중단할 때는 런처의 **재생 중단**을 누릅니다.

저장 위치는 `%LOCALAPPDATA%\AmagadonLauncher\Replays`입니다. 게임 데이터와 사용자 맵이 기록 당시와 일치해야 합니다. 0.3.0/0.3.1 및 0.3.2 기록은 내장된 당시 패치로 별도 리플레이 실행 파일을 생성해 재생합니다. 시작 저장본의 유닛 정의·스프라이트 참조를 현재 실행에 맞게 복원합니다. 리플레이는 영상 파일이 아닙니다. 초기 저장본과 프레임별 입력·명령을 사용합니다. 0.3.3 새 기록(Format 2)은 CRT 난수와 엔진 자체 난수를 모두 기록합니다. 이전 형식에는 엔진 난수가 없습니다. 새 형식도 실제 게임 AI 동기화 문제가 남아 있어 현재 리플레이는 실험 기능입니다. 시작 시 게임 저장·불러오기 과정을 거쳐 상태를 맞추며, 실행 중인 기존 게임에는 연결하지 않습니다. 런처는 게임 종료까지 열어두어야 합니다.

멀티플레이 및 800×600 기록은 지원하지 않습니다. 수동 불러오기는 새 기록으로 나뉘며, 재생 중 사용자 저장·불러오기 명령은 중단 처리합니다. 기록 용량 한도(명령 512MiB 또는 100만 프레임)에 도달하면 자동 기록을 중단합니다. 비정상 종료된 기록은 게임 폴더의 `LauncherReplayWork`에 남으며 완성된 리플레이 목록에 넣지 않습니다. 실제 전투·장시간 재현 검증은 아직 남아 있습니다.

## 랠리 및 하단 지도

1024×768 시험 모드에서 생산 건물은 랠리 방향의 측면부터 원래 충돌 검사를 수행해 출구를 찾습니다. 막힌 방향은 기존 탐색으로 우회합니다. 본진 선택 후 ore를 우클릭하면 새로 생산되는 채취 유닛에 기존 랠리 이동 경로를 설정한 뒤 그 ore의 채굴 명령을 적용합니다. ore2-1을 포함한 ore1/ore2 계열과 자원 가장자리 클릭을 지원하며 실제 클릭 대상 ID를 사용합니다. 다른 유닛과 일반 지점 랠리는 기존 이동 동작을 사용합니다. 하단 스크롤을 6타일 더 허용해 HUD에 가려진 자원을 위로 올릴 수 있습니다. 이전 리플레이 재생에서는 당시 패치를 사용합니다.

새 게임 기록은 커널 이벤트로 동기화하여 프레임당 반복 Sleep 대기를 줄입니다. 원본 게임 속도 단계는 유지하며, 빠름의 실제 설정과 대기 시간은 진단 로그에서 확인할 수 있습니다.

## 빌드 및 검사

Windows의 .NET Framework 4.x C# 컴파일러를 사용합니다. 별도 SDK 설치가 필요 없습니다.

```powershell
.\scripts\fetch-compat.ps1
.\scripts\build.ps1
$test = Start-Process .\dist\AmagadonLauncher.exe -ArgumentList '--self-test' -PassThru -Wait -WindowStyle Hidden
if ($test.ExitCode -ne 0) { throw 'Self-test failed' }
```

자동 검사: 해상도 설정, 반복 적용 시 원본 백업 유지, 기존 DLL 및 미존재 DLL 복원, 필수 게임 파일 누락.
0.3.3-preview는 리플레이 목록, 이벤트 동기화, 하단 스크롤 확장, 생산 출구 방향과 ore 채굴 랠리를 추가했습니다. 기계어 검증 30개 범주와 별도 프로세스의 기록·재생 검사를 통과했지만 제보된 4,182프레임 이전 기록은 완주도 확인했지만 반복 검사에서 AI 동기화 불일치가 남았습니다. 이전 형식의 완전 복구는 보장하지 않습니다. 새 기록과 멀티플레이는 별도 검증 범위를 참고하세요. [HD 분석 및 검증 범위](docs/hd-resolution-status.md)를 참고하세요. 첫 실행에서는 1024×768과 전체 화면 늘리기를 기본으로 적용하고 이후 사용자 설정은 보존합니다.

`--verify-native "원본 EXE 경로"`는 패치 결과와 시험본 생성·재사용·제거, 변조 거부, 원본 보존을 검사합니다. 배포 ZIP에는 버전별 AmagadonLauncher-0.3.3-preview.exe도 포함됩니다. 기존 시험본은 게임 종료 후 다음 실행에서 해시 확인·백업 후 교체됩니다.

## 릴리스

버전은 `src/Launcher.cs`와 PATCHNOTES.md에서 변경합니다. `v0.1.1` 같은 버전 태그를 푸시하면 GitHub Actions가 빌드하고 ZIP/체크섬을 GitHub Release에 올립니다. 최초 0.1.0은 로컬 빌드로 제공됩니다.

참고 프로젝트: [FunkyFr3sh/cnc-ddraw](https://github.com/FunkyFr3sh/cnc-ddraw), MIT 라이선스. 바이너리는 버전과 SHA-256을 고정해 가져옵니다. 원본 게임 실행 파일은 보존하며 배포하지 않습니다. HD 레시피는 해당 EXE를 직접 분석한 것입니다. main 푸시는 빌드 아티팩트를 만들며 preview의 안정판 Release는 게시하지 않았습니다.

런처 시작 시 최신 정식 버전을 확인합니다. 새 버전 안내에서 **확인**을 누르면 다운로드·검증·설치 후 최신 런처를 다시 실행합니다. **취소**하면 현재 버전을 계속 사용합니다. 네트워크 확인 실패 시 **업데이트** 버튼으로 재시도할 수 있습니다.


## 업데이트 복구 (0.3.9 이하)

`System.Collections.ArrayList` 변환 오류는 구버전 자체의 업데이트 처리 오류입니다. 서버의 배포 파일만 변경해 고칠 수 없습니다. [최신 ZIP](https://github.com/japanoxx-afk/amagadon/releases/latest/download/AmagadonLauncher.zip) 전체를 새 폴더에 풀고 `AmagadonLauncher.exe` 또는 동봉한 최신 버전명 EXE를 실행하세요. 기존 0.3.9 EXE 바로가기도 새 파일로 바꿉니다. 사용자 설정은 LocalAppData에 저장되어 유지됩니다.

0.3.12부터 자동/수동 확인은 `Updates.Prepare`를 공유하며 설치 도구의 검증 완료 응답을 받은 후 종료합니다. 설치 결과 로그는 LocalAppData/AmagadonLauncher/updates/각 다운로드 폴더/update-result.log에 남고 로깅 리포트 ZIP에 포함됩니다. `scripts/test-update.ps1 -PackagePath <ZIP>`는 공통 클라이언트 회귀 검사와 x86 부모 프로세스 종료 대기·교체·재실행을 실제 프로세스로 검사합니다.


## IPX 보호 및 진단

0.3.13은 IPX 연결 정보 없음과 초기화 실패 경로를 보호합니다. 성공 시 기존 다음 화면으로 진행하고 실패 시 안내 후 메뉴에 남습니다. 800×600/1024×768 및 리플레이 사용 여부와 무관하게 검증된 게임의 첫 스레드를 재개하기 전에 적용하며 게임 EXE를 덮어쓰지 않습니다. IPX 지원 자체를 설치하거나 TCP/IP로 몰래 전환하지 않습니다.

로그에는 DirectPlay 등록/공급자 목록, 어댑터 상태(주소/MAC 제외), 로컬 네트워크 DLL, 네트워크 객체·공급자 포인터·실패 상태, 보호 횟수와 충돌 덤프가 포함됩니다. IPXWrapper가 설치된 환경의 `ipxwrapper.log`도 포함합니다. IPXWrapper 지원/설치 조건은 [공식 설명](https://github.com/solemnwarning/ipxwrapper/blob/master/readme.txt)을 참고할 수 있으며 이 배포에는 해당 라이브러리를 동봉하지 않습니다.
