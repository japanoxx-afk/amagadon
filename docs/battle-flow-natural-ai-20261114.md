# 탄환·피해·사망 및 자연 AI 진행 시험

## 전투 흐름

`test-battle-flow.py`는 기존 대상 판정 시험을 넘어 원본 탄환 생성 CALL(0x43B69C..0x43B6A9), 탄환 갱신 CALL(0x48CC77..0x48CC94), 명중 피해 함수 0x488E10 및 원본 유닛 스케줄러를 연결한다. CALL 전후 스택/비휘발성 레지스터를 확인한다. 원본 통계 테이블과 실제 유닛 SPR을 사용한다. 기본 유닛 시험 장치에서 로컬 빌드 EXE의 실제 설치 후크를 추출해 함께 실행한다.

서로 다른 로컬 플레이어(1/2), 해상도(800/1024), 카메라(0,0)/(8,6)에서 매 틱 유닛·월드·관리자·난수·시계·탄환 슬롯 및 탄환 전체 0x88바이트를 비교한다. 체력 감소와 생존 플래그 해제가 모두 발생하지 않으면 실패한다. 사망 후에도 60틱씩 추가로 갱신하여 남은 탄환·사후 처리의 상태 일치와 사망 상태 유지를 검사한다.

| 공격 종류 | 최초 피해 틱 | 사망 틱 | 피해 함수 호출 |
|---|---:|---:|---:|
| 0x119 | 4 | 385 | 20 |
| 0x01B | 2 | 783 | 40 |
| 0x223 | 30 | 291 | 14 |

대상은 원본 0x223, 초기 체력 120이다. 주기적 발사는 시험이 요청한다. 공격 명령/대상 자동 탐색부터 시작하는 전체 경기 시험은 아니다. 탄환의 시각 효과 SPR은 아직 연결하지 않았고 모든 특수무기/범위 공격 분기를 다루지 않는다. 일반적인 세 경로에서 탄환 생성→비행/명중→피해→사망이 연결됐다는 의미다.

## 시험 환경에서 확인한 누락

- 지형 배율 테이블 `0x57E2A0`가 없으면 원본 0x4A0DA0이 0을 반환해 피해가 0이 됐다. 평지 배율 100으로 설정했다. 실제 게임의 피해 계산을 수정하지 않았다.
- 장시간 생산 완료 시 UI 갱신 0x427310이 초기화되지 않은 `0x50310C`를 참조했다. 빈 UI 객체를 제공하는 headless 시험 구성을 추가했다.
- 초기 본진의 `mgr+0x222D0` 및 `mgr+0x222F8` 등록이 빠져 AI가 건설 위치를 얻지 못했다. 원본 맵 로딩 `0x44CC45..0x44CC79`와 대조하고 초기 본진만 원본 setter로 등록했다. 이후 계획 인덱스/건설 완료를 강제로 변경하지 않는다.

이 누락은 시험 환경의 문제이며 실제 멀티플레이 불일치 원인으로 확정한 것이 아니다.

## 자연 AI 시험

`diagnose-natural-ai.py`는 원본 AAI/ARO와 실제 SPR 122개를 로딩한다. 활성 AI를 진영별로 나눠 원본 8인 AI 스케줄러에 넣고, 초기 본진·일꾼·ore(0x300)·hydrogen(0x306), 자원 100,000씩에서 시작한다. 계획 인덱스와 건설 완료를 강제로 변경하지 않는다. 서로 다른 로컬 플레이어, 해상도, 카메라에서 매 틱 상태를 비교하며, 생성된 모든 유닛 종류에 실제 SPR이 로딩되어 있는지도 검사한다.

원본 유닛/월드/관리자/난수/탄환 외에 AI 계획 상태, AI 명령 배열, 시야 버퍼도 비교한다. 아직 완료하지 않은 계획이 있으면 exit 2와 INCOMPLETE를 출력한다. 계획 목록 끝에 도달한 경우에도 `full_match=false`이며 모든 선행 건물·연구·특수 공격을 완주했다는 뜻은 아니다. 이 탐색 시험은 일반 회귀 묶음과 분리한다.

완료한 비교 결과 (계획 번호는 0부터 시작):

| 구성 | 비교 틱 | 최종 계획 인덱스 / 목록 길이 | 상태 |
|---|---:|---:|---|
| Earth1, 로컬 1/2 | 4,500 | 73 / 73 | 양측 일치, 4,000틱 표본에서 목록 끝 확인 |
| Elca1, 로컬 2/1 | 6,000 | 75 / 75 | 양측 일치, 3,500틱 표본에서 목록 끝 확인 |
| EAD1, 로컬 3/1 (첫 장기 실행) | 6,000 | 30 / 97 | 양측 일치, 목록 미완료 |
| EAD1, 로컬 3/1 (재실행 연장) | 12,000 | 72 / 97 | 양측 일치, `INCOMPLETE` |

EAD는 5,000틱 표본까지 계획 28에 머물렀지만 6,000틱에는 계획 30으로 진행했다. 실제 Butcher(0x223) 5기와 Evil Eye(0x20D) 건설 상태가 관찰됐다. 양측 동일한 생산 대기였으며, 이를 멀티플레이 불일치로 분류하지 않았다. 12,000틱 재실행에서는 계획 72(BEHOLDER_TERMINAL)까지 진행하고 유닛 슬롯 124개가 관찰됐지만 97개 계획 목록은 끝내지 못했다. 6,000틱까지의 표본은 앞선 실행과 같았다. 남은 계획을 가짜 성공으로 건너뛰지 않았으며 전체 완료 검사 결과는 INCOMPLETE다.

기존 전체 회귀 묶음 `test-simulation-regressions.ps1`도 새 탄환 시험을 포함하여 통과했다. 이후 사망 후 60틱 비교를 추가한 전투 시험도 별도로 재실행하여 통과했다. 새 전투 시험은 1,639쌍의 틱(사망 후 180틱 포함)과 피해 함수 74회를 관찰했다. 기존 역순 유닛 처리 대조군도 3틱째 차이를 검출하여 비교기가 차이를 놓치지 않는지 확인했다. 자연 AI는 초기 계획부터 다시 실행한 짧은 시험과 긴 시험에서 진행 표본이 재현됐다.

실행 예 (작업 폴더에서 PowerShell):

```powershell
$env:AMAGADON_LAB_REAL_SPRITES='1'
$env:AMAGADON_LAB_AI_PLAYERS='2'
$env:AMAGADON_LAB_TICKS='6000'
python scripts/diagnose-natural-ai.py
```

`AI_PLAYERS` 1/2/3은 이 시험 구성의 Earth/Elca/EAD다. 여러 플레이어를 쉼표로 지정할 수도 있다. 결과 및 실패 위치는 gitignored `.tools/natural-ai-real-<players>-*.json`에 남긴다. 동일 플레이어 조합의 동시 실행은 결과 경로가 겹치므로 피한다.

추가로 보완한 시험 초기화:

- 원본 자원 검색은 hydrogen 종류 0x306..0x30B를 찾는다. 잘못 넣었던 0x303을 0x306으로 수정했다.
- 초기 선택 슬롯을 원본 빈 값 -1로 초기화했다. 0으로 채우면 슬롯 0을 선택한 것으로 처리되어 생산 완료 후 로컬 UI 차이가 발생했다. 비교 항목을 숨기지 않고 초기화를 수정했다.
- 원본 시야 버퍼 생성자 0x482730과 플레이어별 시야 배열을 제공했다. EAD 건물 완공 시 필요한 버퍼다.
- USER32!SetRect 외부 호출은 실제 RECT 기록과 stdcall 복귀 규약을 구현한 시험용 대체 함수로 연결했다.
- 실제 SPR 사용 시 긴 위치 검색과 유닛 갱신을 실행할 수 있도록 에뮬레이터의 1회 실행 예산을 선택적으로 5천만 명령으로 늘렸다. 기본 회귀 예산은 그대로이고 게임의 임계치·판정은 변경하지 않았다.

평지 합성 맵, 넉넉한 초기 자원, 렌더링/OS 대체 함수라는 한계가 있다. 일반 자원량의 경제 진행, 모든 난이도/맵, 모든 전투 분기, Windows 실제 경기·DirectPlay 네트워크 전체 루프를 검증한 것은 아니다.

게임 실행 코드, 동기화 검사, 종료 판정은 변경하지 않았다. 새로 확정된 실전 불일치 원인은 없으며 배포용 게임 수정도 없다. 원본 게임 파일과 결과 데이터는 gitignored `.tools`/로컬에만 유지한다.

공격 동작 바이트만 설정하여 원본 공격 디스패처에 진입시키려던 추가 탐색은 피해를 발생시키지 못했다. 공격 명령·애니메이션 초기화가 연결된 성공 사례가 아니므로 통과 범위에 포함하지 않았다.
