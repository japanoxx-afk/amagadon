# 실제 공격 명령·특수 무기·EAD 후반 진행 검증

## 명령에서 결과까지

`test-attack-command-flow.py`는 원본 `0x420788..0x420791` 호출부의 인자 push 및 `CALL 0x40AA40`을 실행한다. 디코딩된 선택 슬롯과 목표 좌표는 시험이 제공하지만, 공격 상태를 직접 쓰거나 주기적으로 탄환을 생성하지 않는다. 첫 명령 이후 원본 유닛 스케줄러와 탄환 갱신으로 공격·사망/회복을 진행한다.

- 실제 CALL 바이트, 스택 변화, 비휘발성 레지스터, 복귀 지점, 양측 EFLAGS 결과를 확인한다.
- 로컬 플레이어 1/2, 내부 너비 800/1024, 카메라 (0,0)/(8,6)인 독립 인스턴스의 유닛·월드·관리자·난수·시계·탄환 상태를 매 틱 비교한다.
- 실제 유닛 SPR 122개를 로딩하고 자식 유닛에도 실제 SPR이 사용됐는지 검사한다.
- 목표 사망/최대 체력 회복 이후 60틱도 비교한다.
- 대공 무기의 지상 목표 거부, 수송 유닛 무기 없음, 특수 기본 무기 예외도 대조 검사한다.

16개 사례에서 4,599쌍의 틱이 일치했다. 지상 목표 거부 대조군 120틱은 별도다. Tiarf는 원본이 허용하는 대상 분류 3/4를 사용하며, 모든 건물을 회복시키는 것으로 가정하지 않는다.

WASP는 탄환을 만들지 않고 직접 피해를 주므로, 탄환 개수를 억지로 요구하지 않는다. 실제 `0x42CED0` 체력 변경 호출과 양측 호출 수를 검사한다. 다른 발사 유닛은 탄환 생성도 계속 요구한다. WARRIOR/NH-59의 지상 목표 거부는 원본 `0x43EDFB`의 무기 +0x0D 대공 제한과 일치했다.

## 별도 특수 무기 분기 시험

`test-special-attack-branches.py`는 무기 5, 9, 16, 29, 30, 33, 34, 35, 38, 39, 47, 49, 65의 13개 사례를 검사한다. 무기 종류와 발사에 필요한 수치(유닛 +0x9CC, +0x9D4 = 10,000)는 시험 초기 상태로 지정한다. 이후 동일한 원본 명령 호출부부터 실행한다. 이는 해당 기술의 자연스러운 획득·시전 UI까지 재현했다는 뜻이 아니다.

13개 사례 모두 피해·사망 및 추가 60틱 비교를 통과했다(2,250쌍의 틱). 특수 처리 종류 2/3/4/5, 일반 탄환 생성 `0x48B170`과 별도 생성 `0x48B300`을 관찰했다. 무기 65는 일회성 효과의 사망 경로를 확인하기 위해 초기 체력 20인 손상된 목표를 사용한다. 회복 무기 53은 사망을 요구하지 않고 위 실제 Tiarf 명령 사례로 검증한다.

## 시험 장치에서 수정한 오류

- 단순 무기 테이블 조회를 원본 맵 로더 `0x44CB07..0x44CC01` 실행으로 교체했다. 원본의 signed -1, 0x35 센티널, 0x117/0x11F 예외를 유지한다. 수송 유닛에 잘못 무기를 부여하던 시험 구성을 수정한 것이며 게임 버그 수정이 아니다.
- 자식 유닛이 발사하는 사례를 부모 포인터만으로 세지 않고 소유자와 실제 생성 진입점으로 계측한다.
- HP를 signed 32비트로 읽는다. 치명타 후 음수 체력을 큰 양수로 오인하지 않는다.
- 최소 사거리 및 지상/공중 제한에 맞는 목표를 사용한다. 잘못된 목표가 거부되는 것은 별도 대조군으로 남긴다.

## 검증과 한계

기존 `test-simulation-regressions.ps1` 전체 묶음이 통과했고, 추가 회복 사례 및 특수 분기 시험도 별도로 통과했다. 두 새 시험을 해당 회귀 묶음에 연결했다.

원본 EXE SHA256: `34f0bf9ed99fbf3ab88c410a3a52a2f6904e7bc7f5b88fb4ebadc935c2e9b466`.
시험 빌드 SHA256: `81cc4227e97071d1cf282560c67c57387bd1a35381f6f2904efb0270ddef6960`.

게임 원본 실행 코드를 Unicorn으로 실행한 오프라인 시험이다. Windows 입력 메시지, DirectPlay 디코더, 전체 렌더 루프, 무기 시각 자료 로딩, 모든 맵과 모든 기술 획득 조건은 포함하지 않는다. 평지 합성 맵을 사용한다. 실제 두 PC 경기 검증과 구분한다. 동기화 검사·종료 판정 및 배포용 게임 코드는 변경하지 않았다.


## EAD 계획 72 정체의 원인과 대조 시험

원본 `AI/Ead1.AAI`에는 SUMMONER(0x204) 건설이 세 번(행 3/5/12), 연결 건물 건설이 네 번(0x205: 행 39, 0x206: 행 40/49/72) 있다. 행 번호는 0부터다. 모두 생존하는 시험에서는 네 번째 연결 건물에 사용할 빈 부모가 없다.

- 원본 소비자 `0x40649E`는 `0x452D30(player, 0x204)`를 호출한다. 이 함수는 부모 +0xA5C가 -1이거나 그 자식이 유효하지 않을 때만 부모 슬롯을 반환한다. 없으면 -1을 반환하여 `0x4064A8`에서 건설을 생략한다.
- 10,232틱의 원본 상태에서 부모 23→자식 60(0x205), 33→83(0x206), 44→69(0x206)를 확인했다. 빈 부모 반환값은 양측 모두 -1이다.
- 선행 조건 0x4552A0은 성공(1), 다른 두 거부 검사는 0이다. ore 90,520 / hydrogen 98,070으로 자원 부족도 아니다.
- `test-ead-addon-parent.py`는 점유된 부모 세 개에서 거부, 네 번째 빈 부모에서 허용되는 원본 함수를 독립 인스턴스로 반복한다. 이는 동기화 불일치가 아니라 양측 공통 정체 조건이다.

후반 분기 검증을 위해 정상 AI 명령 소비자 `0x406160`에 SUMMONER 건설 요청 하나를 추가하는 **대조 입력**을 사용했다. 자원, 계획 인덱스, 기술 완료, 건설 완료 플래그는 바꾸지 않았다. 이 입력 이후 원본 스케줄러가 건설·연결 건물·후반 연구·생산 계획을 처리하여 10,908틱에 97/97에 도달했다(저장 상태부터 676틱). 이 결과를 원본 계획이 무수정으로 자연 완료된 것으로 해석하면 안 된다.

재현 설정(Python 경로는 실행 환경에 맞게 지정):

```powershell
$env:AMAGADON_LAB_REAL_SPRITES='1'
$env:AMAGADON_LAB_AI_PLAYERS='3'
$env:AMAGADON_LAB_TICKS='13000'
$env:AMAGADON_LAB_SUPPLEMENT_EAD_PARENT='1'
python scripts/diagnose-natural-ai.py
```

대조 입력을 제외하려면 `AMAGADON_LAB_SUPPLEMENT_EAD_PARENT`를 제거한다. 보고서의 `supplemental_parent_order_tick` 및 `unmodified_plan_inputs`가 두 조건을 구분한다. 이번 후반 반복에는 로컬에서 생성한 메모리 체크포인트를 사용했으며, 저장/복원 직후와 다음 틱의 전체 상태 일치를 확인했다. 원본 데이터가 포함된 체크포인트는 저장소에 넣지 않는다.


동일 체크포인트에서 대조 시험을 다시 실행해 같은 10,908틱 완료를 확인했고, 12,108틱까지 추가 1,200틱도 비교했다. 두 번째 실행의 총 비교 구간은 1,876틱이다. 계획 목록 소진은 모든 생산 큐와 모든 연구가 완료됐다는 보장이 아니므로 이를 전체 경기/전체 테크트리 자연 완료로 표시하지 않는다. 후반 유닛의 공격은 위 독립 명령 시험으로 따로 확인한다.

이번에 수정한 것은 시험 장치의 무기 초기화·피해 계측·재현 시나리오다. 이 범위에서 새로운 양측 상태 불일치 원인은 발견하지 못했으므로, 배포용 AI/전투 로직이나 동기화 검사는 변경하지 않았다. 원본 EAD 계획의 부모 부족 정체를 임의로 고친 배포 버전도 만들지 않았다.


생성 계측을 추가한 세 번째 후반 반복도 동일한 계획 완료 틱과 이후 1,200틱 비교를 통과했다. 해당 구간의 원본 생성 호출은 0x223×1, 0x204×1, 0x206×1, 0x21C×9, 0x203×4, 0x225×5, 0x221×1, 0x224×1이었다(양측 생성 순서·종류·소유자도 동일). 이 구간에서 WASP/ASTAROTH 생성은 관찰되지 않았으므로, 이들의 자연 생산 완료를 주장하지 않는다. 이 둘의 실제 명령→피해→사망은 별도 원본 유닛 시험에서 검증했다. 모든 후반 연구 효과와 생산 큐 완료까지의 자연 경로는 남은 검증 범위다.


원본 입력 대조군은 30,000틱까지 양측 전체 비교가 일치했지만 계획 72/97에서 정체했다. `diagnose-natural-ai.py`는 이를 성공으로 숨기지 않고 종료 코드 2(INCOMPLETE)를 반환했다.

공중 유닛 생산 미관찰의 추가 단서: 원본 Ead1.AAI의 해당 생산 행은 부모 528(0x210)을 지정한다. 체크포인트에서 원본 `0x4510F0(3, 0x210)`은 -1, `(3, 0x209)`는 슬롯 78을 반환했다. 생산 소비자 `0x406921`은 이 결과가 -1이면 요청을 버리지만, 계획 실행기 `0x454FB1`은 요청을 만든 직후 진행 수를 증가시킨다. 따라서 계획 소진만으로 생산 성공을 보증할 수 없다. 이를 양측 불일치로 확인한 것은 아니며, 올바른 생산 부모/기술 조건을 확인하지 않은 채 게임 데이터를 변경하지 않았다.
