# 실제 유닛 정의 기반 원본 경기 스케줄러 실험 (2026-11-14)

## 결론과 범위

이번 변경은 개발환경 회귀 시험이다. 게임 동기화 검사, 오류 카운터, 종료 조건,
런처/게임의 실행 로직은 변경하지 않는다. 확인된 새 불일치 원인이 없으므로
Lost connection을 해결했다거나 전체 AI를 검증했다고 표현하지 않는다.

`test-native-scheduler.py`는 설치된 원본 EXE와 HED/MFP를 읽고, 빌드된 런처에서
SelectionRuntime/RallySpawn 후크를 추출해 적용한 두 독립 Unicorn 머신을 비교한다.
원본 실행 파일 SHA256은 기존 실험과 동일하게 검사한다.
게임 파일과 추출 데이터는 저장소에 넣지 않는다.

## 원본 코드에서 확인한 처리 순서

- `48CAEF..48CB0E`: 카메라/월드/매니저 인자 설정, `447880` CALL와 반환을 실제 실행한다.
- `447B98..447BA5`: EDI=0에서 시작하여 매니저의 슬롯 포인터 배열을 순회한다.
- `448C70..448C93`: 실제 슬롯 번호를 인자로 `42CEE0` 유닛 갱신 함수를 호출한다.
- `448C93..448C99`: 매번 매니저+4의 현재 개수를 다시 읽고 EDI를 증가시킨다.
  따라서 높은 슬롯에 생성된 유닛은 같은 순회에서 처리될 수 있다. 이미 지나간 낮은
  슬롯 재사용과 동일한 조건은 아니다. 이 특성 자체가 양측 불일치의 증거는 아니다.
- `448CF0` 이후의 화면 표시용 정렬은 별도 목록을 사용한다. 위 슬롯 순회 배열을
  화면상의 Y 순서로 정렬하는 코드는 이 구간에서 발견되지 않았다.
- `42CEE0` 안의 `42DF50`, `435250`, `43B2A0` 행동 처리와 `442080` 이동,
  `42C910` 회전 갱신은 대체하지 않고 원본을 실행한다.
- `4295E0`은 실시간 OS 시계가 아니라 `503C6C * 50`을 반환한다.
- `429260`은 게임 틱뿐 아니라 5/16/32단계 카운터도 갱신한다. 특히 `4296E0`이
  읽는 `503BCC`와 슬롯 하위 4비트를 비교하는 경로가 있다. 시험에서 시간 값만
  직접 증가시키지 않고 `454482`의 원본 CALL을 통해 이 함수도 실행한다.
- `48CC06..48CC63`: 1~8 플레이어 AI 순회, `454EE0` 계획 판단과 `406160` 명령 적용을
  원본 코드로 실행한다. 네트워크 패킷 대기/합의 루프는 이 시험에 포함되지 않는다.

## 실제 데이터와 시험 조건

- `object\earth.aro`, `elca.aro`, `ead.aro`, `neutral.aro`를 원본 `40DE10`으로 읽는다.
  각 파일은 6바이트 헤더, 400바이트 저장 포인터, 1000바이트 목록,
  50개의 0x39DC바이트 정의로 구성된다. 로더 결과와 파일의 200개 정의를 바이트 비교한다.
- 본 시험의 지상/공중 이동 대상은 0x12, 0x113, 0x21C, 0x17, 0x1B,
  0x119, 0x11B, 0x223, 0x226이다. 정의 200개 로딩을 200종의 전체 행동 검증으로 세지 않는다.
- 9개 AAI 전체 행을 읽되, 원본 로더처럼 4바이트 고정 폭 숫자를 사용한다.
  Elca2의 인접 숫자 `2884096`을 공백 분리로 읽으면 잘못 해석된다.
  이 파서 보완은 시험 코드의 정확성을 위한 것이며 게임 원본의 오류 수정이 아니다.
- 양측 로컬 플레이어(1/2), 화면 폭(800/1024), 커서, 카메라(0,0)/(8,6),
  스택 초기 패턴을 다르게 한다. 공유 월드와 초기 명령은 같게 한다.
- 매 틱 전체 유닛 구조체, 매니저, 월드/점유 격자, 난수 상태, 틱/단계 카운터,
  원본 체크섬, 효과 객체를 비교한다. AI 시험은 뇌 상태와 생성 명령도 비교한다.
- 슬롯 방문 순서의 오름차순/중복 없음, 양측 방문 순서 일치, CALL의 인자 및 반환 주소,
  ESP와 callee-saved 레지스터 보존을 검사한다. 생성된 유닛도 다음 비교 대상에 자동 포함한다.
- 본진이 완성된 초기 상태를 만들기 위해 원본 카운트 등록 함수를 사용한다.
  생성/이동/행동 루틴의 반환값이나 자원/유닛 질의 결과는 모킹하지 않는다.

## 시험 구성

1. 9종 각각 4기에서 시작하여 600틱 실행한다. 스매셔는 원본 생성 경로에서
   자식 객체도 생성하므로 실제 처리 객체 수는 8개이다. 정지 상태만 시험하고 통과하지
   않도록 실제 위치 변화와 회전 호출을 기록한다.
2. 3개 난이도별로 8개 AI 플레이어를 배치하고 600틱씩 실행한다. 세 진영의 9개 계획,
   실제 본진/일꾼, 자원 차감, 생산 완료와 새 슬롯의 같은 순회 편입을 비교한다.
3. 대조 시험에서만 한쪽 원본 루프의 슬롯 순서를 역순으로 바꾼다.
   위치 불일치를 검출해야 통과한다. 이는 게임이 실제로 역순 처리한다는 증거가 아니다.

기계 판독 결과와 자산/런처 해시는 `.tools/native-scheduler-results.json`,
실패 시 함수/행/틱 정보는 `.tools/native-scheduler-failure.json`에 남긴다.
기존 실패 파일은 삭제하지 않으므로 결과의 실행 시각/현재 출력도 함께 확인한다.

## 명시적인 한계

- SPR 파일의 실제 프레임/충돌 사각형 대신 공통 시험용 sprite 메타데이터를 사용한다.
  ARO의 방향/애니메이션 시간/이동 수치와 원본 회전 로직은 사용하지만, 실제 그림의
  모든 프레임 및 크기가 다른 유닛 조합의 충돌까지 검증한 것은 아니다.
- 지형은 평탄한 합성 월드이며, 시야/효과 버퍼도 시험에서 초기화한다.
  `4BD550`, `4BD640` 화면 제출 함수는 생략한다. 렌더링 검증이 아니다.
- 9개 AI 계획을 로드했어도 모든 행을 끝까지 진행하지 않는다. 실제 도달한 계획
  인덱스를 결과에 기록한다. 전체 테크트리·공격·수송·사망·특수능력 분기 검증은 남아 있다.
- 모든 후크의 모든 분기, DirectPlay, OS 메시지/렌더링 타이밍, 실제 두 PC 경기는 포함하지 않는다.
- 이 시험만으로 실제 경기의 Lost connection 원인이 없다고 판정하지 않는다.

## 실행

```powershell
& 'C:\Users\seo\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' scripts/test-native-scheduler.py dist/AmagadonLauncher.exe
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-simulation-regressions.ps1 -Python 'C:\Users\seo\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
```

원본 경로를 바꾸려면 Python 스크립트의 두 번째 위치 인자에 원본 EXE를 지정한다.
HED/MFP는 해당 EXE와 같은 폴더에서 읽는다. 게임 실행이나 종료, 파일 패치는 수행하지 않는다.

## 이번 실행 결과

- 9종 유닛 × 600틱 = 5,400개 양측 틱 비교 통과. 군사유닛/자식 객체를 포함한
  원본 회전 함수 호출 24,000회(한쪽 기준)를 관찰했다.
- 3개 난이도 × 600틱 = 1,800개 양측 AI 경기 틱 비교 통과.
  8플레이어 AI 판단은 한쪽 기준 14,400회 실행되었다.
- 각 AI 사례는 16객체에서 32객체로 증가했다. 새 슬롯 16~31이 생성된 순회에서
  갱신되는 경우도 양측 순서와 전체 상태가 일치했다.
- 계획 진행 인덱스는 모든 AI에서 1에 머물렀다. 후반 계획 실행을 검증했다고 해석하면 안 된다.
- 역순 대조 시험은 18틱째 유닛 위치 차이를 검출했다.
- 생성 런타임 동일성, simulation-isolation, selection-runtime(원본 AAI 포함),
  path-production, unit-lifecycle, native-scheduler, selection-sync-isolation 통과.
- 위 통합 시험에서 새 원인은 재현되지 않았다. 실행 로직 패치나 새 배포 버전은 만들지 않았다.
