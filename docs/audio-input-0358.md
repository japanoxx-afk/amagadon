# 0.3.58 BGM 경로와 입력 재확인

이전 생성 C#에 BGM 경로의 백슬래시와 종료 문자가 중복 이스케이프되어 있었다. 결과 데이터는 단일 경로 구분자와 NUL 대신 중복 구분자와 문자 그대로의 backslash-zero를 포함해 실제 파일명과 다르다. generator는 정확한 `BGM\04-into the war.wav`+NUL 바이트를 Hex로 생성하도록 바꿨다. 기존 비어 있지 않은 맵 음악 경로는 원본 함수에 그대로 넘기며, 빈/null 경로에서만 기본 파일을 사용한다. 설치된 Build 산출물의 전체 바이트 일치 및 로컬 실제 파일 존재를 검증했다. 이전 검사는 fallback 포인터 분기만 확인하여 문자열 오류를 놓쳤다.

DirectInput 알림이 누락되면 원본/HD 공통 InputRecovery에서 최대 100ms timeout을 기다리던 것을 16ms로 줄였다. 이벤트가 정상적으로 전달되면 기존 즉시 처리 경로를 유지한다. 포커스가 없는 동안 입력을 읽지 않는 보호와 실패 후 제한된 재획득, 원본 프레임 데드라인은 유지한다. 이것은 알림 누락 시 지연 상한의 개선이며 인터넷 지연 또는 원본 해상도에 한정된 원인을 입증하지 않는다. 최근 첨부 경기의 설정은 양측 NativeHD=True라서 해당 자료로 800/1024 차이를 검증할 수 없다.

NetworkState에 audioDriver(0x2240d44), musicState(0x4f8628), nativeTickBatch(0x503bc8), nativeFrameInterval(0x50bc64)을 추가했다. 판독 전용이며 음악 볼륨/게임 속도를 강제하지 않는다. 알림 빈도가 최악 조건에서 약 10Hz→62.5Hz가 되므로 입력 스레드 재확인 횟수는 증가할 수 있다. 실행 중 게임은 바꾸지 않고 다음 실행부터 적용한다.

검증은 scripts/test-selection-runtime.py의 실제 설치 문자열/파일 검사 및 scripts/test-input-recovery.py --input-only의 원본 x86 알림/포커스/키보드/데드라인 검사다. 전체 오래된 layout 회귀 테스트는 별개이며 현재 메시지 위치 예상값이 과거 값인 기존 실패가 있어 이번 입력 검증에 포함하지 않았다. 실제 음악이 귀로 들리는지와 두 PC 간 체감 응답은 미검증이다.
