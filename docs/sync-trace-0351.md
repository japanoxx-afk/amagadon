# 멀티플레이 동기화 기록 형식 (0.3.51)

`진단 기록 및 충돌 덤프 수집`을 켠 뒤 새 게임을 실행하면 적용된다.
핫키 설정 버튼은 0.3.51에서 제거했다.

## 수집 지점과 범위

- 원본 0x454487의 0x408300 호출 직전, 네트워크 입력 수신 후 명령 적용 경계에서 수집.
- 같은 simulation clock에서 중복 수집하지 않는다. 멀티플레이/경기 중에만 동작한다.
- 1,024개 고정 크기 순환 기록. 시간 길이는 게임 속도에 따라 달라진다.
- 첫 nativeSyncErrors 관찰 후 순환 기록을 동결해 종료 메시지 대기 중 덮어쓰기를 막는다.
- 새 경기(manager 변경 또는 clock 역행)에는 세대를 올려 새로 기록한다.
- 시뮬레이션 스레드에서는 파일·네트워크·Windows API 호출을 하지 않는다.
- 유닛/명령/난수 상태는 읽기만 하며, 진단 전용 메모리에만 기록한다.
- CRT RNG는 TEB의 이미 존재하는 TLS 슬롯에서 읽는다. 슬롯이 없거나 64 이상이면 0xffffffff.

## 파일

진단 세션 폴더에 `sync-trace.dat`와 `sync-trace.json`을 저장하며 리포트 ZIP에 자동 포함된다.
5초마다 저장하고, 첫 오류·처리되지 않은 예외·디버그 종료 이벤트에서도 저장을 시도한다.
감시 프로세스도 갑자기 종료되면 마지막 저장 이후 기록은 유실될 수 있다.
기존 약 30초/250ms 상태 이력에는 각 샘플의 네트워크 상태도 추가했다.
실행 시 HED/MFP SHA256도 기록해 양측 게임 데이터 차이를 비교한다.

DAT: 4096바이트 헤더 + 1024 × 2048바이트 슬롯, little endian.
헤더: +0 magic STR1, +4 마지막 sequence, +8 마지막 clock, +12 동결 여부,
+16 동결 clock, +20 경기 세대, +24 런타임 manager 주소(비교 대상 아님), +28 활성화.
슬롯 위치: `4096 + (sequence & 1023) * 2048`.

| 슬롯 offset | 내용 |
| --- | --- |
| 0 | 시작 sequence(작성 중 0) |
| 4 | simulation clock |
| 8 | 엔진 RNG 인덱스 |
| 12 | 프레임 간격 |
| 16 | 로컬 플레이어(양측 비교 제외) |
| 20 | native sync 오류 수 |
| 24 | 유닛 상태 지문 |
| 28 | manager 유닛 슬롯 수(최대 1700) |
| 32..71 | 소유자별 상태 지문 10개 |
| 76 | 종료 sequence |
| 80 | x87 FPU control word(16비트) |
| 84 | CRT RNG seed 또는 0xffffffff |
| 88 | 경기 세대 |
| 128..1535 | 0x52f210의 명령/입력 영역 1408바이트 |

유닛 지문은 ID/type/x/y/health/alive/owner를 섞는다. 전체 시뮬레이션 상태의 완전한
체크섬은 아니며, 충돌 가능성이 있다. CRT RNG 차이도 단독으로 원인이라고 단정하지 않는다.
두 번 복사한 버퍼에서 시작/종료 sequence와 세대가 맞는 슬롯만 JSON에 색인한다.
raw DAT에 색인되지 않은 미완성 슬롯이 있을 수 있으므로 JSON의 stableFrames를 사용한다.

## 양측 비교

`python scripts/compare-sync-traces.py player1.zip player2.zip`

각 ZIP에서 가장 최근의 동결된 trace를 우선 선택한다. 같은 경기인지 먼저 확인한다.
겹치는 clock에서 최초 유닛/소유자 지문 차이, 난수/FPU 차이, 플레이어별 최종 명령 패킷 차이를
출력한다. 로컬 입력 임시 영역은 패킷 비교에서 제외한다. 기록 차이는 조사 단서이며
근본 원인 확정이나 멀티플레이 오류 해결을 의미하지 않는다.

## 검증

- 컴파일된 런타임을 x86 에뮬레이션해 기록 내용·레지스터/플래그·원본 상태 보존 검사
- 실제 설치된 0x454487 호출 경계와 원래 함수의 스택 유지 검사
- 동일 clock 중복 제거, 오류 동결, 새 경기 재시작, 1024슬롯 순환, 진단 OFF 검사
- 원본/HD EXE를 정지 상태로 실행해 패치 및 원격 ring 저장 검사
- 두 번 읽기 중 갱신된 슬롯 및 경기 세대 혼합 거부 검사
- 비교 도구의 최초 상태/난수/명령 차이와 손상 슬롯 회귀 검사
- 실제 진단 자식의 정상 종료/예외 덤프 및 ZIP의 DAT/JSON 포함 검사
