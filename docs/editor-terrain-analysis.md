# ACE 지구 연결 지형 구현 및 검증

## 파일 구조 정정

Earth.ms는 276바이트 헤더 + 60개 × 0x3384바이트 레코드 + 4바이트 후미이다. 이전의 36바이트 헤더 및 타일 표 +0x2c4 추정은 폐기한다.
레코드 자체 기준 격자는 +0/+0x68/+0xd0/+0x138, 각 8열 × 13행(x×13+y)이다. 이름은 +0x1b2, 유형 +0x1d0, A/B 지형 +0x1d2/+0x1d3, 타일 표 +0x1d4(8×13×15×4 uint16), 후미 240바이트이다.
Earth.pi는 24바이트 헤더와 32×32 색인 타일이며 +18 ushort가 타일 수이다. 팔레트는 별도 Palette/earth.pal이다.
HED는 8바이트 헤더와 72바이트 항목이다. +0 MFP 오프셋, +4 이름 64바이트, +68 크기이다.

## 구현

원본 15번을 57번 언덕경사-10시, 14번을 58번 언덕경사-2시로 복사한다. 앞쪽 8×6의 네 격자와 타일 참조/픽셀을 180도 회전하고 지형 A/B를 교환한다. 원본 타일 뒤에 93개를 추가하며, 기존 레코드와 보조 행 및 후미는 보존한다. 유형 4/5를 유지한다. 6/7이 반대 방향이라는 근거는 없었다.

TerrainPatch는 원본과 산출물 SHA-256을 고정한다. MFP는 배타적 핸들로 열어 뒤에 추가하고 flush한 뒤 HED를 원자적으로 교체하고 LauncherBackups에 백업한다. 게임과 에디터가 동일 적용 코드를 사용한다. 기존 리플레이는 백업 HED의 정확한 해시, 변경된 두 항목, 추가 자료의 정확한 해시, 원본 MFP 접두부의 해시를 모두 검사한다.

## 검증

- 격리된 실제 ACE에서 두 방향을 배치하고 ramp-validation.acz 저장 후 다시 열었다. 메모리의 맵 연결 배열에서 57번과 58번이 각각 1개 유지됨을 확인했다.
- verify-ramp-boundaries.py: 1,100개 반사 경계/장애물 조건 및 원본 1,100개 회귀 조건 통과.
- verify-ramp-pipeline.py: 0x428260 전체 배치/정리 경로에서 57/58 유지 확인. 난수와 최종 UI 갱신만 대체했다.
- verify-reverse-ramps.py: 연결 지형 0x428ef0 실행 후 0x423aa0/0x423b80 setter 출력 인자로 두 방향 96셀의 충돌 값 확인. 이전 기본 지형 경로 검사는 연결 지형 검증으로 대체했다. 실제 게임 길찾기 테스트는 아니다.
- terrain-patch-fixture.cs: 정확한 산출물 해시, 원본 MFP 모든 바이트 보존, HED 두 항목만 변경, 백업, 반복 적용, 수정 자료 거부, 기존 리플레이 자료 검증 통과.
- 휠 세로 스크롤과 패널 너비 조절은 0.3.26에서 실제 UI 및 x86 검사 완료.

## 한계

회전한 바위/그림자는 북쪽 경사로의 자연스러운 조명 표현에 한계가 있다. 실제 게임에서 양방향 유닛 이동과 모든 주변 지형 조합은 실플레이 검증하지 않았다. 새 지도의 플레이어도 같은 지형 확장이 필요하다. 6시/12시는 이번 범위에서 제외했다. 실행 중인 사용자 원본 에디터와 미저장 지도는 변경하지 않았다.
## 0.3.28 배치 조건 수정

A/B 교환만으로는 원본의 비대칭 주변 검사 범위가 뒤집히지 않았다. 42ea90의 지형/연결 조회를 표시 영역 중심 기준으로 반사하고 결과 마스크를 되돌린다. 57/58 및 지구 언덕 이름/A/B 조건을 모두 만족할 때만 적용한다. 배치 전 2×2 평지 삭제를 건너뛰고, 재검사에서는 자신의 연결 앵커를 이웃 장애물에서 제외한다. 원본 14/15와 다른 행성은 기존 경로를 유지한다.

## 0.3.30: 생성 성공과 통로 연결 검증 분리

사용자 테스트.acz의 57번 앵커 (10,6)는 존재했지만 북서 언덕 경계 위쪽 평지에 떨어져 있었다. 0.3.29의 가까운 허용 위치 탐색은 이 잘못된 기준을 유지했다. 57번 지형 조회의 Y 반사식에 -3을 적용하여 실제 앵커 (10,9)에서 표시 영역이 절벽을 덮도록 수정했다. 자신의 연결 앵커를 제외하는 역좌표에도 같은 보정을 적용한다. 58번은 변경하지 않는다.

검증은 원본 사용자 프로세스에 쓰지 않고 읽어온 맵 객체를 격리된 x86 실행 환경에 복제하여 수행했다. 기존 앵커 및 그 연결 표시 레이어를 제거한 사본에 새 경사를 원본 전체 배치 경로로 생성했다. 원본 0x427010의 지형 내보내기 부분(0x42735e의 유닛 처리 직전까지)을 실행한 결과로 이미지와 최종 이동 불가 비트를 검사했다. verify-ramp-gap.py는 (20,6) ↔ (25,12)를 제한된 경계 안에서 4방향 탐색해 수정 전 양방향 단절/수정 후 양방향 연결을 검증한다. 원래 언덕 지형 배열은 바뀌지 않았다. 기존의 생성/충돌 복사 검사만으로 통로 연결을 검증했다고 간주하지 않는다.

사용자의 원본 ACZ 및 실행 중 미저장 지도는 수정하지 않았다. 기존 잘못 배치된 경사는 새 에디터에서 제거 후 다시 배치해야 한다. 실제 게임에서의 유닛 크기와 이동 엔진을 포함한 실플레이 검증은 이 격자 검사와 별개다.
