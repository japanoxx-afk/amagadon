# 0.3.67 동기화 진단: 확인한 사실과 한계

기준: origin/main `91ed12f`, 태그 v0.3.66. 작업 브랜치 `codex/desync-state-trace`.
원본 Armageddon.exe SHA256:
`34f0bf9ed99fbf3ab88c410a3a52a2f6904e7bc7f5b88fb4ebadc935c2e9b466`.
Capstone으로 원본 PE의 VA를 RVA로 변환하여 읽었다. HD 디스어셈블리를 원본 근거로 사용하지 않았다.
전달받은 `claude/desync-analysis-20261102.md` 파일은 작업 폴더에서 찾지 못했다. 사용자 메시지의 분석을 인계 자료로 사용했다.

## 결론

멀티플레이 불일치의 근본 원인은 **미확정**이다. 0.3.67은 진단 버전이며,
게임 명령, 자원 차감, 경로 탐색, 동기화 오류 판정은 수정하지 않는다.
로컬 UI의 공유 상태 쓰기는 후보이며, 해당 쓰기를 삭제하거나 오류 검사를 끄지 않았다.

## 원본에서 재확인한 경로

- `407686..40769B`: 로컬 플레이어 `4E7270`을 읽고 해당 슬롯의 word24를 인자로 `427530` 호출.
- `427BA4`: 해당 패킷 word26을 읽는다. `427BB0`에서 `mgr+player*4+2221C`에 쓴다.
  그 뒤 `427BC9`의 로컬 플레이어 비교가 나온다. 따라서 쓰기 자체가 로컬 비교로 보호되지는 않는다.
- `454429..45448C`: 조건에 따라 `407010` 호출 → `4081D0` → 로컬 슬롯 복사 →
  멀티플레이 `482CF0` 또는 싱글플레이 `408300` → 공통 진단 경계 `45448C`.
  이 순서만으로 각 함수의 모든 조기 반환과 네트워크 대기를 포함한 틱당 실행 빈도까지 확정할 수는 없다.
- `41D1AB..41D1E6`: 명령 3C/3D에 따라 종류 205/206 설정, word26으로 `41F530` 호출,
  플레이어 대기 모드 `51BC50`에 3C 기록.
- `425293..4252A0`: 클릭한 개체가 `mgr+player*4+2221C`와 같은지 검사한다.
  이어지는 경로는 연결 개체의 A5C 상태도 검사하며, 일부 분기는 A5C를 -1로 바꾼다.
  따라서 기존 32바이트 유닛 기록이 같다는 사실이 모든 게임 상태의 동일성을 뜻하지 않는다.
- `406160`은 플레이어 1..8 작업 루프이다. `40668A`는 `425090`을 호출한다.
  `48CC5E`의 호출 직전에 AI 플레이어 갱신 루프가 있다. 순수 UI 전용 함수라고 분류할 근거가 없다.
- `4851C0` 인코더에는 명령 word24와 좌표를 별도로 인코딩하는 분기가 있다.
  유휴 커서 바이트 차이를 패킷 손실이나 원인으로 단정하지 않는다.
- SelectionRuntime `sync`의 로컬 분기에는 대표 선택 상태 쓰기가 있다.
  `world_resources`는 렌더 호출의 복귀 경로를 조절한다. 기존 설치 후크 테스트는 시뮬레이션
  메모리 불변을 확인하지만, 이 사실만으로 모든 상위 호출의 간접 영향까지 배제하지 않는다.

**인계 자료에서 수정한 중요한 점:** `4A20B5`는 y를 10비트 왼쪽 이동한 뒤 x를 더하고,
`4A20BB`는 `map + (y*1024+x)*2 + 12F808`을 읽는다.
점유 격자의 행 간격은 맵 폭과 무관하게 **2048바이트**다.
작은 맵을 `width*height*2` 연속 바이트로 해시하면 잘못된 행들을 읽는다.
추가 진단은 각 행에서 실제 폭만큼 읽고 고정 행 간격으로 다음 행에 이동한다.

커서 파생값의 모든 간접 사용처와 로컬 선택 상태의 모든 시뮬레이션 사용처에 대한
완전한 데이터 흐름 증명은 끝나지 않았다. 원본과 패치본의 실제 두 PC 대조 경기 역시 수행하지 않았다.
따라서 원본 버그/런처 버그 중 어느 쪽인지 확정하지 않는다.

## 기존 리포트 재비교

기존 RP/RPP와 보존된 로컬 리포트를 확장된 비교 도구로 다시 비교했다.
두 사례 모두 공통 1,024프레임이며 엔진 RNG의 최초 차이는 없었다.
사례 A는 5778에서 P2 유닛 163의 위치 차이, 사례 B는 10211에서 P2 슬롯 135의
활성/종류/위치/체력 차이가 다시 확인됐다. 두 사례 모두 새 확장 기록이 없으므로
자원·건설 대상·격자의 당시 값을 소급 복원할 수 없다. 사례 B는 인계 자료상 .61/.62 혼용이다.

## 기록 형식

기존 2048바이트 프레임 중 1536..2047의 512바이트만 사용한다. 기존 포맷과 패킷은 그대로다.

| 확장 내부 오프셋 | 내용 |
|---|---|
| 0 / 4 | magic HST1 / version 1 |
| 8 / 12 / 16 | 격자 폭·높이(셀), 읽은 바이트 수 |
| 20 | 상태: 0=null map, 1=유효, 2=범위 밖 크기 |
| 24 | mgr+711A, word를 32비트로 확장 |
| 32..383 | 플레이어 1..8, 각각 44바이트 |
| 384..447 | 위에서 아래로 16개 가로띠 FNV-1a 해시 |
| 448..511 | 예약, 0 |

플레이어 레코드는 `<4i2H6i>`:
자원 A8C0/A8E8, 건설 대상 2221C, 모드 51BC50, 종류 4FA618(word),
플래그 4F9E40(word), 51BC28, 51BCF4, 51BD48 두 dword, 51BE00 두 dword.
띠 i의 행 범위는 `[floor(i*h/16), floor((i+1)*h/16))`이다.
FNV 초기값 811C9DC5, 소수 01000193, 바이트 단위, 32비트 모듈러 연산.
셀 크기는 각각 1..1024일 때만 읽는다. null/잘못된 크기를 정상 해시로 해석하지 않는다.

기존 진단 ON·멀티플레이·유효 매니저 검사 뒤 수집한다. pushfd/pushad로 보존하고,
게임 영역을 읽기만 한다. 확장 기록을 마친 뒤 기존 프레임의 종료/시작 시퀀스를 커밋한다.
세대, freeze, ring wrap 규칙은 유지한다. raw DAT에 포함되므로 기존 로깅 리포트 ZIP에 자동 포함된다.
JSON에는 배열을 중복 저장하지 않고 확장 오프셋/크기/버전/행 간격만 명시한다.

`scripts/compare-sync-traces.py left.zip right.zip`의 `firstHiddenStateDifferences`가
항목별 최초 차이와 양쪽 값을 출력한다. `hiddenStateCommonFrames=0`은 기존 버전 또는
비교 가능한 확장 기록 부재이며, 상태가 같다는 뜻이 아니다. 커서 값은 로컬 입력 때문에
다를 수 있으므로 명령 프레임과 자원/건설/격자 차이의 선후 관계를 함께 해석해야 한다.

## 검증

- `test-selection-runtime.py`: 원본 EXE에 실제 후크 바이트 설치, JMP 45448C에서 시작,
  내부 CALL 연결과 원본 복귀 454491까지 실행. 레지스터, 플래그, 스택, 원본 mov eax 결과 확인.
- 빌드한 x86 런처의 `SelectionRuntime.Build`를 별도 x86 프로세스로 호출하여 추출한
  재배치 주소의 바이트로 같은 테스트를 수행했다.
- 8명 모든 필드, 비정방형/작은 격자, 고정 행 간격, 16개 해시, 크기 오류,
  진단 OFF에서 무효 지도 포인터를 읽지 않음, 최대 256×256 맵, 게임 메모리 불변 확인.
- 기존 freeze/세대 초기화/1024 슬롯 순환 테스트와 선택·명령·리플레이 패킷 회귀 테스트 통과.
- 오프라인 ZIP 비교: 필드/띠 최초 차이, torn slot 제외, 구버전 확장 없음 처리 검증.
- 실제 배포 ZIP 업데이트 테스트: 체크섬, 사용자 설정 보존, 잠긴 파일 롤백, 구버전 엔트리 교체, x86 업데이트 인계 및 재시작 통과.
- 입력 레이아웃 전체 테스트나 실제 두 PC 경기 통과를 주장하지 않는다.

`benchmark-state-trace.py`는 같은 격자 해시 어셈블리를 x86 네이티브 테스트 프로세스에서
실행한다. Unicorn 소요 시간을 성능 수치로 사용하지 않는다. 20회 준비 후 200회 측정:

| 맵 타일 크기 | 바이트/프레임 | 중앙값 ms | p95 ms |
|---|---:|---:|---:|
| 64×64 | 131072 | 0.0969 | 0.1413 |
| 128×128 | 524288 | 0.4041 | 0.4149 |
| 256×256 | 2097152 | 1.5949 | 1.8197 |

CPU: AMD Ryzen 9 7900. 이는 격자 해시만의 비용이며 전체 진단/실제 게임 FPS 측정은 아니다.
구형 CPU와 경쟁 부하에서는 비용이 커질 수 있다. 매 프레임 수집을 유지하고 샘플 누락으로 비용을 숨기지 않았다.

## 다음 경기에서 확인할 것

양측 모두 0.3.67, 진단 로깅 ON으로 같은 경기를 실행하고 종료 직후 양측 로깅 리포트를 수집한다.
자원/건설 대상/모드/격자 중 가장 먼저 달라진 항목과 명령 실행 순서를 비교한다.
격자는 해시이므로 개별 셀 값이나 쓰기 호출 스택까지 복원하지 못하며, 모든 상태 후보를
기록한 것은 아니다. 한 번의 재현으로 원인이 반드시 확정된다고 보장하지 않는다.
계정·토큰·원본 게임 데이터·사용자 리포트는 저장소 및 배포 패키지에 포함하지 않는다.
