# 길찾기·생산 오프라인 반복 비교 (2026-11-14)

`scripts/test-path-production.py`는 원본 EXE의 실제 x86 코드를 두 개의 독립된
Unicorn 상태에서 실행한다. 경기 실행이나 신규 사용자 리포트가 필요하지 않다.
원본 EXE SHA256을 고정 검사하고, 빌드된 런처의 RallySpawn.Build를 x86 C#
프로세스에서 호출하여 실제 배포 후크 바이트를 가져온다.

## 실행

프로젝트 루트에서 기존 `.tools`의 pefile/unicorn/keystone 및 Python을 사용한다.

```powershell
$env:PYTHONUTF8='1'
$env:AMAGADON_LAB_SEED='20261114'
python scripts/test-path-production.py dist/AmagadonLauncher.exe
# 또는 원본 EXE 위치를 두 번째 인자로 지정
powershell -File scripts/test-simulation-regressions.ps1 -Python <python.exe>
```

원본 위치는 AMAGADON_GAME_EXE로도 지정할 수 있다. 출력은 비공개 `.tools`의
path-production-results-<seed>.json / path-production-results.json이다.
실패하면 종료 코드가 실패이고 path-production-failure.json에 재현 seed와
마지막 길찾기/출구 조건을 남긴다. 실패를 정상 비교로 처리하지 않는다.
실행 중인 게임/런처/서버는 건드리지 않는다.

## 실제 실행한 경로

- 471760 → 4AAC50: 원본 탐색 테이블 초기화. 초기화 없이 실행했을 때 경로
  길이가 0으로 나오는 불완전한 fixture를 폐기하고 원본 초기화부터 실행한다.
- 471790 → 4AC4EE: 실제 경로 탐색. 열린 지형/우회벽/닫힌 벽/미로,
  1~2셀 크기, 고정 seed의 서로 다른 출발·목적지. 각 지형 140회 연속 호출로
  8비트 캐시 세대 순환도 지난다. 양쪽 로컬 플레이어/화면 폭/유휴 커서/
  호출 전 스택 내용은 다르게, 동기화 입력과 지도는 같게 만든다.
- 경로 좌표·반환값·상태·4EB2B0부터 8300바이트 작업 영역 해시를 비교한다.
  점유 격자가 변하지 않았는지, 스택과 callee-saved 레지스터도 검사한다.
  비교 범위를 과도하게 넓히면 의도적으로 다르게 둔 화면 폭까지 포함되는
  문제를 확인하고 탐색 작업 영역으로 한정했다.
- 44CF0A/44CF5B: 실제 설치된 생산 출구 후크와 원본 사방 출구 탐색/복귀.
  4A26F0/4A2600/4A25A0/4A28C0 및 4A2070 점유 조회를 대체하지 않는다.
  무장애/지형 장애/활성 유닛 장애, 5개 랠리 조건, 생산자 ID 1/17/257/1699.
- 447400 → 452990: 빈 슬롯 탐색. 처음/중간/마지막 슬롯, tombstone 보류,
  1700칸 가득 찬 상태. 반환 슬롯과 manager count를 비교한다.
- 430AC9..430AFA: 기본 생산 타이머 420틱. 21틱당 진행 증가와 카운터를 검사.
- 430BC6..430C08: 완료 시 타이머 리셋·대기열 감소·자식 생성 호출 인자.
  4종류 및 특수 변종 조합 8개. 실제 자식 생성 CALL 직전에 멈춘다.

탐색/점유/슬롯 검사를 가짜 결과로 대체하지 않는다. 유일한 대체 함수는
492280 debug printf이다. 지도/유닛 정의는 합성 fixture이며 실제 전체 게임
스냅샷을 복원한 것은 아니다. 상태에 따른 분기 조건을 실제 맵 데이터 전체로
검증했다는 의미도 아니다.

## 결과 및 검출력

seed 20261114: 길찾기 560쌍, 생산 출구 60쌍, 슬롯 10쌍, 타이머 420쌍,
완료 상태 8쌍에서 불일치 없음. 기존 선택/건설/AI/FPU 회귀 묶음도 통과.
다른 seed 20261115로 경로 조건을 바꾸어 추가 실행한 결과도 통과했다.
두 시드에서 길찾기 총 1,120쌍, 생산 출구 총 120쌍을 비교했다.
두 번째 실행은 약 14.0초였으며 이는 에뮬레이션 테스트 시간이다.

양측 지도 한쪽에만 벽을 넣으면 실제 경로 좌표가 달라지는 positive control을
통과한다. 생산 출구도 오른쪽 장애물을 넣으면 (160,240)에서 (128,144)로
바뀐다. 처음 fixture는 충돌 범위를 0으로 초기화하여 이 검사가 실패했고,
실제 2×2 충돌 범위와 지도 인자를 연결한 뒤 통과했다. 따라서 무조건 동일한
반환값만 비교하는 시험이 아니다.

기존 test-rally-runtime.py의 기대 후크 집합이 ore-rally 추가 전 2개로 남아
현재 빌드에서 실패하는 문제도 수정했다. 기대 후크 4개를 정확히 검사하고
랠리 캐시용 메모리도 실제 할당 크기에 맞췄다. 해당 회귀 시험은 다시 통과했다.

## 미검증 범위

전체 생산 타이머 분기(종족 보정·전력·모든 업그레이드), 41F830의 전체 자식
객체 생성/초기화, 이동 매 틱 충돌 해소 및 여러 유닛의 동시 점유 변경,
전체 경기/네트워크 패킷 스케줄은 아직 이 시험에 포함되지 않는다.
화면 폭 전역값을 바꾸는 시험이며, 두 렌더러 전체 실행을 비교한 것은 아니다.
CPU 실측 성능 시험도 아니다. 이번 조건에서는 새 불일치 결함을 재현하지
못했으므로 게임 로직이나 오류 판정은 변경하지 않는다. 테스트 개선만으로
Lost connection을 해결했다고 표현하지 않는다.
