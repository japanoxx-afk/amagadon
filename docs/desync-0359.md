# 13.zip 양측 경기 분석 (0.3.58)

상대 20261102-011350-234-18176, 로컬 20261102-011344-706-48220은 양측 0.3.58 경기다. 두 설정 모두 NativeHD=True로 기록됐다. native first comparison은 동일 clock 10616/sequence 10604이며 로컬/상대 64바이트 패킷이 양측에서 정확히 서로 뒤집혀 보존됐다. fingerprint는 28/62, 62/28. reason=1, missingHistory=0이다. 이는 같은 비교 입력에 대해 양측 게임 상태가 달라졌다는 증거이며 패킷 누락을 단정할 근거는 아니다. 최종 프로세스 exit=0으로 기록됐다.

원본 1024프레임 이력에서 최초 위치/체력/활성 지문 차이는 clock 10601, 플레이어 1이다. unitCount=239. 명령 상태 지문 및 엔진 난수 인덱스는 전체 공통 프레임에서 같다. helper의 첫 상세 캡처는 clock 10619/10624로 5프레임 차이가 있다. ID 183(type 0x223, owner 1)의 active=1/0 차이, 건설 중 ID 220/225의 체력 차이가 보이나 캡처 시계가 달라 이것을 최초 원인이라고 단정할 수 없다. 본진/명령/해상도를 강제하거나 checksum 오류를 무시하는 패치는 하지 않았다.

0.3.59는 집계 지문만 있던 한계를 보완한다. 기존 1024프레임 trace와 같은 호출에서 최근 64프레임에 대해 유닛별 32바이트 상태를 기록한다. 프레임 슬롯은 64+1700*32=54464바이트, 64슬롯과 전역 헤더 포함 0x354000바이트로 제한된다. 실제 기록은 현재 유닛 수(최대1700)만 처리한다. 새 데이터는 runtime+0x281000부터이며 전체 allocation은 0x5d5000으로 확장한다. 리플레이 sidecar/게임 메모리 영역과 겹치지 않는다. 진단 OFF에서는 기존 trace 진입 guard에서 돌아와 새 기록도 하지 않는다.

각 레코드: id i32, type u16, owner u8, active u8, x/y/health/target/timer i32, order u8, raw4d0/raw13b9/raw10 u8. id=-1은 빈 슬롯이다. 함수는 pushfd/pushad로 호출 상태를 보존하며 게임 메모리는 읽기만 한다. 프레임별 시작/완료 sequence와 generation을 검증해 helper가 쓰기 중인 슬롯을 제외한다. 기존 주기 저장과 frozen archive에 unit-trace.dat/json을 함께 보존한다. 보관 메모리는 약3.5MB 추가되며 파일 저장은 기존 주기 캡처에서 수행한다. 실제 네트워크 장기 플레이 부하 측정은 아직 하지 않았다.

scripts/compare-sync-traces.py는 unit-trace가 있으면 같은 clock에서 최초로 다른 유닛 ID와 필드 값을 표시한다. 기존 리포트에는 새 개별 프레임 기록이 없으므로 소급 복원할 수 없다. 이번 단일 근본 원인은 미확정이며 진단 보완 버전이다.
