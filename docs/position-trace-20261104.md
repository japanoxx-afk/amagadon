# DISCONNECTION / DRAW 조사: 좌표 변경 호출 기록

현재 상태: **근본 원인 미확정, 끊김 방지 수정 아님. 정식 배포하지 않음.**

2026-11-03 양측 0.3.70 기록은 21803프레임에 P1 유닛 236의 X좌표가
1931/1926으로 갈라졌고, 21805에 점유 격자 해시가 달라졌다. 비교 구간의
명령 패킷(유휴 커서 제외)과 엔진 난수 인덱스는 같다. 기존 32바이트 유닛
기록으로는 좌표 변경의 호출자나 이동 내부 상태를 복원할 수 없다.

원본 좌표 setter `0x43F550`, `0x43F590`에 읽기 전용 진단을 추가했다.
진단 ON, 멀티플레이 경기, sync generation 활성 상태에서만 기록한다.
sync 첫 불일치 동결 이후에는 추가 기록하지 않는다. 8192개의 128바이트 슬롯이
오래된 항목을 덮어쓰며, 보관 시간은 이동량에 따라 달라진다. 30초 보관을 보장하지 않는다.

각 항목은 틱, 세대, 유닛 ID/종류/소유자, setter와 호출자 주소, 요청값,
변경 전 X/Y, unit+0x400..0x43F의 미해석 바이트를 담는다. 요청값은 setter 인자이며
최종 원시 좌표와 같다고 가정하지 않는다. 미해석 바이트에는 PC별 값이 있을 수 있어
차이가 있다는 이유만으로 동기화 오류 원인이라고 판정하지 않는다.

원본 prologue가 사용할 256바이트 스택 영역을 피해 진단 스택을 만들고
레지스터/플래그를 복원한다. 첫 구현 검증에서 스택 scratch 차이가 검출되어 이를 보완했다.
상태 변경은 별도 진단 할당 영역뿐이며 원본 setter prologue는 그대로 실행한다.
동기화 검사, 난수, 통신, 유닛 이동, 승패 판정은 변경하지 않았다.

Windows 수집기는 시퀀스 앞/뒤, 세대, 두 번 읽기를 확인한 뒤
`position-trace.json`을 원자적으로 저장한다. 기존 로깅 ZIP의 JSON 수집 대상에 포함된다.
비교 스크립트는 첫 차이 유닛의 전후 2틱 좌표 호출 목록을 `positionHistory`에 첨부한다.
구버전 기록에 이 파일이 없으면 빈 목록이며 해당 정보를 추론하지 않는다.

검증:
- Windows csc 개발 빌드 통과. 표시 버전 `0.3.70-preview`로 정식 0.3.70과 구분.
- 빌드 EXE의 실제 설치 JMP/재배치 대상으로 원본 스택·레지스터·플래그 비교 통과.
- 진단 OFF/동결/싱글플레이에서는 기록하지 않는 검사 통과.
- 기존 선택/DirectPlay codec/리플레이 패킷/MFP 9종 에뮬레이션 검사 통과.
- x86 Windows 시험 프로세스에서 8192슬롯 중 미완료 1개·다른 세대 1개를 제외한
  8190개 저장 확인. 2MB가 넘는 JSON도 저장되도록 전용 직렬화 한도를 적용했다.
- 기존 sync report 비교 회귀 검사 통과.

실제 두 PC 경기, 실제 렉 비용, 이번 유닛 이동 분기의 재현/수정은 미검증이다.
전체 경기 재생이나 경로 전체 스냅샷도 아니다. 게임 데이터를 저장소에 넣지 않았다.
본 코드를 끊김 해결 버전이라고 배포하면 안 된다.
