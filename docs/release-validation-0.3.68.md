## 적용

- origin/main `d8d965c` 및 v0.3.67을 확인한 뒤 `codex/claude-0.3.68` 브랜치에서
  `git am claude-0.3.68.patch` 적용. 1개 커밋, 11개 파일, 충돌 없음.
- 기존 수정되지 않은 파일 및 추적되지 않은 사용자 파일은 보존했다.

게임 코드를 바꾸거나 검증을 생략하지 않았다. 이후 F10/목록/생산 배너/점수판 OK/업그레이드 바까지 통과했다.

## 수동 화면 검증

정식 빌드 EXE의 Launcher/DiagnosticReports 구현을 로드하는 x86 검증용 부트스트랩을 사용했다.
사용자 설정을 덮어쓰지 않도록 Core.Home을 테스트 폴더로 돌리고, 게임 데이터도 별도 복사했다.
검증용 코드와 복사 데이터는 .tools에만 두며 배포하지 않는다.

- 복사한 option.dat의 음악 값과 음악 음량을 각각 0으로 설정했다.
- 런처의 게임 실행 버튼으로 '배경음악 꺼짐' 질문 표시를 확인했다.
- 화면에서 '예'를 클릭했다. 음악 값 +0x0C=1, 음량 +0x04=100을 파일에서 확인했다.
- LauncherBackups의 option 파일이 변경 전 복사본과 바이트 단위로 동일함을 확인했다.
- 원본 option.dat SHA256은 전후 동일했다:
  `9e1829aeeb8107ba4ceee45d16b0bc0603ad844202bbdfb077522c58262d06e3`.
- 합성 양측 ZIP으로 실제 Compare/ShowResult를 호출하고 화면을 확인했다.
  '숨은 상태 공통 프레임', P2 자원 100/99 및 격자띠7 차이, 버전 0.3.68/0.3.67 경고가 표시됐다.
- 복사본 게임 실행 및 메인 메뉴/멀티플레이 플레이어 선택 화면 진입, 테스트 인스턴스 종료를 확인했다.
  기존 사용자 런처·게임·서버를 종료하지 않았다.

## 한계

- 실제 두 PC 경기, 경기 시작 후 BGM 청취, 실제 경기의 music.stream/music.playing 값은 확인하지 못했다.
- 첫 UI 부트스트랩은 DPI 초기화를 생략하여 입력 좌표 확인이 제한됐다. 비교 결과 확인에는 DPI 초기화를 적용했다.
  첫 복사본 실행의 진단 감시자는 테스트용 Home 경로 때문에 정상 수집 경로로 사용하지 않았다.
  이 실행의 network-state가 없다는 것을 게임 음악이 재생되지 않았다는 근거로 해석하지 않는다.
- 음악 테스트의 스트림 성공은 원본 x86 코드와 대체 Miles 호출을 통한 검증이며 실제 오디오 출력 검증이 아니다.
- 이 버전은 **진단 버전**이다. 멀티플레이 동기화 불일치의 근본 원인을 해결했다고 주장하지 않는다.
- 양측 모두 같은 0.3.68을 사용해야 한다. 이전 진단은 플레이어1의 누락된 BC28 값을 복원할 수 없어 미상 처리한다.

## 배포 검증

빌드 ZIP의 package.json 파일별 SHA256과 별도 ZIP 체크섬을 확인한다.
