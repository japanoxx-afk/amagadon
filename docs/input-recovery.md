# Alt+Tab 입력 복구 (0.3.16)

사용자 제보: Alt+Tab으로 다른 프로그램에 갔다가 게임 창을 클릭하면 마우스가 움직이지 않는다.

## 원본 코드에서 확인한 경로

- `0x494f33`: WM_ACTIVATE의 WA_ACTIVE(1)만 허용하고 WA_CLICKACTIVE(2)를 건너뛴다. 앞서 WA_INACTIVE로 설정한 `0x572b5c`가 1로 남으면 `0x4909a0` 마우스 스레드는 입력 처리를 중단한다.
- `0x4906f5`: GetDeviceData 뒤 이벤트 수를 HRESULT보다 먼저 확인한다. 오류 시 이벤트 수가 0이면 재획득이 실행되지 않는다. DIERR_INPUTLOST만 인식해 DIERR_NOTACQUIRED도 처리하지 못한다.
- `0x4909ac`, `0x4909fb`: 마우스 알림 이벤트를 무한 대기한다. 장치가 해제된 상태에서 알림이 더 오지 않으면 입력 읽기에 의존하는 재획득 역시 실행되지 않는다.
- 실제 시험 실행 로그에서는 `pausedForFocus=0`인 상태에서도 GetDeviceData가 NOTACQUIRED, Acquire가 OTHERAPPHASPRIO를 반환했다. 래퍼가 전달하는 포커스 상태만으로 실제 전면 여부를 판단할 수 없다.

## 수정

`InputRecovery`는 `NetworkGuard`의 지원 해시 검증 후 첫 스레드가 재개되기 전에 적용한다. 원본/현재 HD/지원되는 이전 리플레이 실행 파일의 원본 바이트를 모두 검사한다. 게임 EXE 파일을 다시 만들거나 리플레이 해시를 변경하지 않는다. ACE에는 적용하지 않는다. 진단 기록 옵션을 꺼도 복구 패치는 동작한다.

활성화 1/2는 원본 키보드·마우스 획득/상태 초기화 경로로 보낸다. 마우스 알림 대기는 100ms로 보완하며 정상 이벤트가 오면 즉시 처리한다. 타임아웃은 성공 알림과 구분해 기록하고, 대기 자체가 실패하면 원래 종료 경로를 따른다.

게임 프로세스에서 GetModuleHandleA/GetProcAddress로 GetForegroundWindow를 찾아 실제 게임 HWND(`0x572b50`)와 비교한다. DLL 주소를 다른 프로세스에서 추정하지 않는다. 전면 게임에서 놓친 포커스 중단 플래그만 복원한다. 게임의 명시적인 마우스 중단 플래그(`0x5727d0`)는 변경하지 않는다. 다른 창이 전면이면 입력 읽기/획득을 수행하지 않는다.

GetDeviceData의 HRESULT를 이벤트 수보다 먼저 검사한다. INPUTLOST/NOTACQUIRED이면 전면 여부를 확인하고 Acquire 한 번, 성공 시 GetDeviceData 한 번만 재시도한다. 실패가 계속돼도 같은 호출 안에서 반복하지 않는다. DI_BUFFEROVERFLOW의 유효한 이벤트는 처리하고, 실패한 호출의 버퍼는 처리하지 않는다. 한 번의 복구가 계속 실패해도 무한 루프를 만들지 않는다. [Microsoft의 입력 손실 안내](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee416314(v=vs.85))가 설명하는 장치 재획득과 무한 반복 주의사항을 참고했다.

실행 코드와 상수는 RX 페이지, 카운터/API 캐시는 별도 RW 페이지에 둔다. `0x490998` 함수 뒤 패딩에는 진단 카운터 주소만 저장한다. 전체 카운터·HRESULT·포커스 상태는 `input-state` 진단으로 남아 기존 ZIP 리포트에 들어간다.

## 검사 범위

`scripts/test-input-recovery.py`가 실제 원본/HD x86 코드를 Unicorn에서 실행한다. Windows/DirectInput 호출은 테스트 대역이며 실제 바탕화면에 입력하지 않는다.

- 원본 WA_CLICKACTIVE에서 중단 플래그가 남는 문제, 오류/이벤트0에서 획득이 누락되는 문제 재현
- 활성화1/2와 상위 워드, 비활성/잘못된 활성값 분기
- 오류1e/0c 및 이벤트0/64, 재획득 성공/우선권 실패/연속 손실, 재시도 상한
- 정상 읽기/버퍼 오버플로, 실패 버퍼의 가짜 움직임 차단
- 알림/타임아웃/대기 실패, 실제 백그라운드 입력 제외
- 놓친 포커스 복귀만 복원하고 명시적 마우스 중단은 유지
- API 동적 검색과 코드 페이지 RX, 함수 복귀의 스택·보존 레지스터

`scripts/network-guard-fixture.cs`는 실제 원본/HD/이전 리플레이 프로세스를 정지 상태로 생성해 두 패치 설치와 진단 카운터 읽기를 확인하고 해당 시험 자식만 종료한다. 디스크 해시가 변하지 않는지도 검사한다.

실제 게임 시작·패치 설치 및 진단 기록을 확인했다. 사용자 입력 감지로 창 전환 자동 조작을 중단했으므로 실제 Alt+Tab 반복/클릭 복귀 및 장시간 플레이의 완료 검증은 남아 있다.

## 0.3.17 추가 검증

키보드의 GetDeviceData 오류 0x8007000C/0x8007001E에 전면 확인, Acquire 1회, 이전 키 상태 초기화, 읽기 1회를 적용한다. DI_BUFFEROVERFLOW는 성공 데이터로 처리한다. 시작 시 마우스 Acquire의 일시적 우선권/장치 손실 오류는 알림 스레드를 파괴하지 않는다. 다른 실패는 원본 정리 경로를 유지한다.

FramePacing은 0x482dfe의 원본 시계 호출에만 적용한다. 경과 시간이 기존 간격 미만일 때 Sleep(0)으로 준비된 스레드에 양보하고 시계를 다시 읽는다. 긴 sleep이나 게임 틱 변경은 없다. 자동 검사에서 이미 지난 마감·0 간격·반복 대기·32비트 시계 래핑과 스택/보존 레지스터를 확인했다. OBS 부하 감소량 및 장시간 플레이는 미검증이다.
