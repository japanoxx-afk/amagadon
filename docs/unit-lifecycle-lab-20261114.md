## 결과

- 신규 자식 생성 36쌍: 소유자1/2/8, 종류12/113/21C 반복, 슬롯/소유자/종류/
  활성 상태/모든 생성 메모리 및 지도·관리자 일치. 실제 점유 변경도 확인.
- 재사용 슬롯 생성 24쌍: 기존 객체는 남기고 재사용 가능한 비활성 상태로
  시작한다. 1회 할당한 같은 슬롯을 원본 초기화로 반복 재사용하며 양측 일치.
  사망 애니메이션 전체를 실행한 시험은 아니다.
- 마주보기2기/교차4기/밀집8기 각각100틱: 총300틱 일치.
  충돌 거부/재탐색 지점 실행 건수는 각각7/12/61회.
- 힙 잔여값 00/A5: 생성 직후153바이트가 달랐지만, 추가100틱의 메모리 읽기
  추적에서 해당 바이트를 읽은 횟수0. 나머지 유닛 상태·지도·관리자·RNG 일치.
  이러한 미사용 바이트를 불일치 원인으로 단정하거나 무조건 지우지 않는다.
- 대조 시험: 한쪽의 유닛 처리 순서를 의도적으로 역순으로 바꾸면 0부터 센
  3번째 틱에서 위치 차이를 검출한다. 검출기가 실제 충돌 결과 차이를 잡는다.
  게임이 실제로 양쪽에서 다른 순서로 처리한다는 증거는 아니다.

초기 합성 정의에는 sprite 테이블/방향 개수/크기가 없어서 조회 실패 또는
0 나눗셈이 발생했다. 정의를 보충하여 원본 조회를 실행했고, 게임 결함으로
보고하지 않았다. 외부 경계 대체를 늘려 오류 경로를 숨기지 않았다.

## 해석과 한계

이번 시험 범위에서는 새로운 시뮬레이션 불일치 결함을 발견하지 못했다.
따라서 게임 로직·오류 판정·종료 임계치를 변경하지 않는다. 버전은0.3.74 유지.

정의/그래픽 메타데이터는 합성 fixture다. 실제 모든 종족·유닛의 데이터 조합을
읽어서 검증한 것은 아니다. 이동은 원본 명령으로 경로를 만든 후 방향 정렬을
마친 이동 상태에서 시작한다. 렌더링/회전 애니메이션/AI 스케줄러 전체를
실행하는 완전한 경기 루프는 아니다. 같은 authoritative 유닛 순서를 준
경우의 생성·이동·충돌을 검사한다. 실제 게임의 스케줄러가 그 순서를 항상
동일하게 유지하는지에 대한 전체 증명과 실제 두 PC 검증은 포함하지 않는다.
이 결과를 Lost connection 완전 해결로 표현하면 안 된다.
