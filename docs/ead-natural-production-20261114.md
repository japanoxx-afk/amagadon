# EAD 자연 생산·연구 완료 검증

## 최종 변경

`build-ead-ai.py`의 계획 보정을 두 원본 계획 선택 경로(`0x45623C`, `0x456209`)에 설치한다. EAD 계획 인덱스 6..8에만 적용하며, 다른 진영의 계획과 원본 게임 파일은 변경하지 않는다.

1. 원본 EAD AAI의 네 공중 유닛(0x226 EXA FLAMING, 0x227 TRANSPORTER, 0x228 WASP, 0x229 ASTAROTH) 생산 행은 부모를 `0x210`(NH-60 Cocoon)으로 지정한다. 자연 진행에서 이 생산 부모가 없어 원본 `0x4510F0` 탐색이 실패한다. 이를 원본 자동 보충 함수 `0x4558D0`가 같은 네 유닛에 지정하는 `0x206`(Beholder Terminal)으로 맞춘다. 이름으로 추정한 값이 아니라 원본 생산 분기표를 근거로 한다. 원본 명령 소비자·스케줄러를 거쳐 0x206에서 ASTAROTH가 생성되는 분리 시험도 수행했다.
2. 연결 건물 0x205/0x206 요청 수가 SUMMONER(0x204) 건설 수를 초과하는 지점 직전에 일반 SUMMONER 건설 행을 삽입한다. Ead1은 원본에서 부모 3개에 연결 건물 4개를 요구한다. 원본 부모 탐색은 연결 슬롯이 이미 점유된 부모를 거부한다. 보정 후 계획 행 수는 Ead1 98개, Ead2 115개, Ead3 111개(원본 97/115/109개)다. 원본 8,000바이트 버퍼 안에서만 처리하고 재호출해도 중복 삽입하지 않는다.

3. 원본 `0x455C90`의 부족 수량 보충 루프는 낮은 번호의 유닛부터 검사하며, 생산 건물의 대기열이 꽉 차도 그 요청을 선택하고 함수를 끝낸다. 같은 상태에서 이 과정을 반복하면 뒤에 있는 유닛이 계속 밀린다. 실제 후반 상태를 고정하고 명령 버퍼를 매회 비운 500회 호출에서 실제 발행된 222회 모두가 `0x220 → 0x205`, 대기열 8인 요청이었다. `0x455E69`의 원본 비용·선행 조건 검사는 유지하고, EAD 후보의 원본 생산 부모를 `0x4510F0`로 찾은 뒤 부모 부재 또는 대기열 8 이상이면 원본 다음 후보 경로 `0x455E72`로 진행한다. 자리가 있으면 기존 우선순위를 유지한다. 목표 수량·계획 번호·RNG에는 새 상태를 추가하지 않는다. 다른 진영에는 적용하지 않는다.

4. 생산이 앞당겨지면 Ead2가 인구 79/한도 74에서 방어 건물의 재료 유닛을 기다리는 상황도 나타났다. 뒤의 인구 건설 행에 도달하지 못할 수 있으므로 `0x454F08`에서 EAD 대기열 선두의 실제 ARO 인구 비용을 검사한다. 현재 한도가 200 미만이고 부족할 때만, 원본 대기/건설 중·비용·선행 조건 검사를 거쳐 일반 ORDER BRAIN 건설 요청을 발행한다. 건설 완료나 인구 수치를 쓰지 않고, 한도 200에서는 추가 요청하지 않는다. 계획 번호와 목표 수량도 변경하지 않는다.

## 원본 정책 유지

원본 `0x454F7D`에서 첫 생산 행이 넘어가는 동작은 목표 수량 등록이며, `0x455C90`가 이를 계속 보충한다. 따라서 **계획 번호가 넘어간 사실만으로 생산 완료나 생산 실패를 판정하지 않는다.**

생산 대기열에 반드시 입장한 뒤 다음 계획으로 넘어가도록 하는 재시도 보호도 시험했으나, 원본의 보충 생산 정책과 결합하면 후반 테크 진행이 크게 늦어졌다. 해당 생산 요청 재시도 보호는 최종 코드에서 제거했다. 인구 보완은 이 보호와 분리하여 실제 대기열의 인구 부족을 검사하는 일반 건설 요청으로 구현했다. 원본 `0x454FAC` CALL, `0x454F7D` 비교, `0x455B0C` 자동 보충 부모 지정은 그대로 유지하며 회귀 검사에서 원본 바이트를 확인한다. 별도 분리 시험에서는 0x206과 0x209 모두 공중 유닛을 생성할 수 있었으므로 단순한 건물 번호 차이는 결함으로 단정하지 않았다.

인구 상한 200, 자원 차감, 건설·생산·연구 시간, RNG, 동기화 검사, 오류 카운터와 종료 판정은 변경하지 않는다. 계획 번호·유닛 생성·연구 완료 플래그를 강제로 올리지 않는다.

## 반복 검증 방법

```powershell
# 실제 확인한 상대 입력 일정으로 처음부터 재현
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-ead-natural.ps1 -Python <python.exe> -Launcher dist/ead-ai-verified-final/AmagadonLauncher.exe -Variants 0 -CombatWaveTick 39001
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-ead-natural.ps1 -Python <python.exe> -Launcher dist/ead-ai-verified-final/AmagadonLauncher.exe -Variants 1 -CombatWaveTick 200001
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/test-ead-natural.ps1 -Python <python.exe> -Launcher dist/ead-ai-verified-final/AmagadonLauncher.exe -Variants 2 -CombatWaveTick 30001
```

장기 검사는 짧은 회귀 검사와 분리되어 있다. `diagnose-natural-ai.py`가 실제 원본 ARO/AAI/SPR, 원본 스케줄러·명령 소비자·생산·연구·전투 처리를 실행한다. 로컬 플레이어 3/1, 화면 폭 800/1024, 카메라 위치와 표현용 CRT 난수 시드가 다른 두 인스턴스를 매 틱 비교한다. 유닛 전체 바이트, 점유 격자, 관리자 상태, AI 목표, 명령, 게임 RNG, 시계, 탄환·효과·시야와 성공한 생성 이벤트를 비교한다.

통과 조건은 각 계획 종료, 네 공중 유닛의 실제 생성, 해당 AAI가 요구하는 연구 모두 완료·진행 중 아님, 이후 1,000틱 추가 일치다. 성공한 원본 생성 함수의 반환을 기록하며 단순 함수 진입이나 생산 요청을 생성 성공으로 세지 않는다. Ead1/2/3의 서로 다른 연구 ID 수는 7/16/11개다. 이는 각 계획의 연구 전체이며 게임에 존재하는 모든 연구 조합과는 구분한다. Ead1은 연구 행 8개 중 ID 78이 중복된다. 원본 0x45515A~0x4551B8은 완료 값이 0이 아니면 그 연구 행을 넘기므로 중복 행을 추가 단계 연구로 세지 않는다. 연구 분기는 행의 수량 필드를 사용하지 않는다. 원본 EXE에서 이 완료 판정도 직접 재확인했다.

인구 200에서 평화 상태로 무한히 생산할 수는 없다. `AMAGADON_LAB_COMBAT_PRESSURE=1`은 실제 인구 한도와 공중 유닛 대기열 선두의 ARO 인구 비용을 비교해 생산이 기다리는 상황에서 적 전차 8기·HUNTER 2기까지 일반 생성하고 원본 공격 명령을 주는 통제된 상대 입력이다. 정지 상태·낮은 체력의 EAD 지상 전투 유닛을 우선한다. 원본 공격·탄환·피해·사망으로 발생한 손실 후 생산을 검사하며, EAD 유닛 체력/사망/인구/연구를 직접 수정하지 않는다. EAD 건설·생산·연구는 원본 AI 계획으로 진행한다. 인구 보완 전 Ead2 대조 시험의 계획 종료 시 한도는 138이었다. 고정 180을 공격 시작 조건으로 두었던 초기 시험은 후속 생산을 막는 인구 부족을 해소하지 못했으므로 실제 한도 기반으로 시험 입력 조건을 고쳤다. 인구 부족 자체를 게임 크래시나 동기화 오류로 취급하지 않는다. `-CombatStartTick`으로 전투 입력의 시작 시점을 재현할 수 있다.

### 인구 상한과 상대 입력의 구분

소규모 집중 공격에서는 인구 2짜리 손실을 보충 생산이 곧바로 채워 인구 8이 필요한 ASTAROTH가 오래 기다렸다. 이는 생산 부모가 없어 요청 자체가 거부되는 결함과 구분한다. Ead2는 이 입력만으로 완료했으나, Ead1/Ead3는 추가 전투 조건도 시험했다. `-CombatWaveTick` 이후 상대 전차 40기·HUNTER 8기까지 일반 생성하고, 실제 ARO 인구 비용이 큰 지상 전투 유닛부터 네 공격자를 한 표적에 배정한다. 새 공격자는 생성 직후 시험 지도에 배치하고 기존 유닛을 순간 이동시키지 않는다. 공격 대상·좌표·틱과 인구 사용량을 결과에 남긴다. 이는 통제된 상대 병력 공급이며 EAD의 자연 생산으로 세지 않는다. EAD 자원·체력·인구·생산·연구를 직접 변경하지 않는다.

장기 시험 시간을 줄이기 위해 동일 빌드에서 처음부터 실행하고 양측 일치를 확인한 x86 전체 메모리/레지스터 체크포인트를 사용했다. Ead1은 39,000틱, Ead3는 30,000틱에서 재개하고 각각 39,001/30,001틱부터 추가 상대 입력을 허용했다(실제 입력은 250틱 주기). 같은 체크포인트를 독립적으로 불러와 재실행하여 결과도 대조한다. 체크포인트에서 계획·연구·생산 값을 교체하지 않았다. `test-ead-natural.ps1 -Variants 0 -CombatWaveTick 39001` 또는 `-Variants 2 -CombatWaveTick 30001`은 같은 입력 일정을 처음부터 실행할 수 있는 경로이며, 체크포인트 파일은 배포하지 않는다. 기본 추가 입력 시점은 30,000틱이며 `-CombatWaveTick 200001`로 이 시험 입력을 끌 수 있다. 추가 입력 없는 Ead1/Ead3가 완료했다고 주장하지 않는다.

전투 음성 선택에 필요한 GetLastError/TlsGetValue/SetLastError의 OS 연결만 시험 환경에서 제공한다. 원본 CRT rand 연산과 게임 난수는 유지한다. 초기 미매핑 TLS 오류는 게임 수정이 아니라 시험 환경 보완 사항이다. 틱별 5억 명령의 유한 검사 한도를 사용하며 한도 초과를 게임 크래시나 불일치로 보고하지 않는다.

`test-ead-ai.py`는 설치된 후크의 실제 진입과 원본 호출, EAD 계획 보정·멱등성, 원본 목표 등록·생산 요청 정책, 공중/지상 생산 부모, 스택·레지스터·양측 상태를 검사한다. `test-simulation-regressions.ps1`에도 포함한다. 별도 전체 원본 함수 시험에서 본진 대기열을 8, 다음 생산 건물 대기열을 1로 두면 원본은 일꾼 요청을 반복하고 수정본은 다음 생산 가능한 전투 유닛을 요청한다. 대기열 7이면 원래 일꾼 우선순위를 유지하고, 모든 생산 건물이 가득 차면 해당 요청을 보내지 않는다. Earth/Elca의 원본·수정본 상태도 동일하다. 외부 분기가 들어오는 `0x455E72`를 덮지 않는지 함께 검사한다. 이 제어된 경계 시험과 자연 생산 완료 시험은 구분한다.

통제된 상대 입력에 쓰는 HUNTER의 원본 공격→탄환→피해→사망 시험을 `test-attack-command-flow.py`에 추가했다.

## 한계

평지 합성 맵과 넉넉한 초기 자원을 사용한다. 실제 경제 경쟁, 임의 지형·모든 연구 조합, Windows 화면·DirectPlay를 포함한 두 PC 경기는 검증하지 않는다. 상대 입력이 통제된 에뮬레이션을 무개입 실전 경기로 표현하지 않으며, 이 검사를 통과했다고 Lost connection 전체 해결을 의미하지 않는다. 테스트 산출물과 게임 자산은 로컬 `.tools`에만 두며 저장소에 포함하지 않는다.
